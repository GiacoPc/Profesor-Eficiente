## 1. Objective

Correct the resolver so it cannot emit an apparently valid, continuation-authorizing context package when required source artifacts, source identity, task dependencies, provenance, or gate evidence are missing or contradictory.

## 2. Confirmed defects in the frozen implementation

1. The resolver unconditionally emits `blockers: []`.
2. Core governance files are silently omitted when absent.
3. Text-frequency ranking is used without a declared dependency manifest or authoritative dependency resolution.
4. The package emits a generic `next_authorized_action` despite having no verified gate result.
5. The code does not implement C2 dependency expansion, C3 forensic selection, or a verifiable fail-closed gate.
6. Git identity collection does not validate that the working tree is clean or distinguish tracked source state from uncommitted modifications.
7. Source hashes are calculated from working-tree bytes without proving those bytes match the declared Git tree.

## 3. Required correction behavior

- Validate a non-empty bounded objective; invalid input must fail without producing an authorizing package.
- Resolve repository identity, explicit branch, HEAD, and tree. Ambiguous or unavailable identity must block.
- Require every configured C0 artifact. Missing required C0 sources must create a blocker and prevent authorization.
- Bind each selected artifact to a Git blob identity and SHA-256 of the exact bytes used. Detect uncommitted changes and fail closed by default.
- Resolve task dependencies through an explicit, versioned dependency manifest. Keyword ranking may rank optional context only; it must never decide authority or dependency completeness.
- Preserve source status and evidence labels where provided. Missing status/provenance for a source used as authoritative must produce UNKNOWN and block.
- C2 dependencies must be expanded transitively and deterministically. Cycles, missing nodes, invalid references, and contradictory identities must block.
- C3 forensic context must be opt-in and explicitly labelled historical/forensic; it must never silently supersede current authority.
- Emit blockers derived from observed validation results. The implementation must not contain a constant empty-blocker shortcut.
- `FAIL`, `UNKNOWN`, or `CONFLICT` must yield `BLOCKED`, no authorized next action, and a non-zero CLI exit code.
- F21: this resolver is read-only. Any future write integration must independently enforce declared target ref, verified target HEAD, explicit branch argument, post-write re-fetch, and result identity verification. This resolver must not claim to enforce writes it does not perform.
- Output must be deterministic for the same source state, objective, policy, and dependency manifest, excluding explicitly volatile metadata such as generation timestamp.
- No token-savings percentage may be claimed without a documented measurement experiment.

## 4. Acceptance criteria

- **RCR-01 — Input validation:** empty/whitespace objective is rejected.
- **RCR-02 — Source identity:** package includes repository, branch, HEAD, tree, and exact Git blob identities; unverifiable identity blocks.
- **RCR-03 — Required C0:** each required C0 source is mandatory; a missing source blocks.
- **RCR-04 — Dirty tree:** dirty tracked or untracked inputs are rejected by default or explicitly represented as untrusted and blocking; they cannot be silently treated as canonical.
- **RCR-05 — Dependency graph:** transitive C2 resolution is deterministic; missing/cyclic/contradictory dependency graph blocks.
- **RCR-06 — Provenance:** every selected source includes path, Git blob SHA, content SHA-256, and declared status/evidence class or an explicit UNKNOWN.
- **RCR-07 — Fail-closed:** FAIL/UNKNOWN/CONFLICT results block and do not carry an authorized next action.
- **RCR-08 — No false empty blockers:** every blocker is generated by a validation result; tests must prove known failure cases produce blockers.
- **RCR-09 — C3 isolation:** forensic inputs are opt-in and labelled non-authoritative unless separately approved.
- **RCR-10 — Reproducibility:** equivalent source state/policy/objective produces the same semantic package and source list.
- **RCR-11 — F21 boundary:** resolver performs no writes and explicitly disclaims write-control enforcement; any future write adapter must have separate tests for explicit-target enforcement.
- **RCR-12 — Independent L2:** an English-language independent audit mandate and evidence package must be reviewed by an external auditor before any governance promotion.

## 5. Stop conditions

Any failed acceptance criterion, missing evidence, unknown behavior, conflicting source identity, or inability to reproduce a test result blocks closure. Self-audit is not independent L2. No criterion is closed by a model assertion alone.
